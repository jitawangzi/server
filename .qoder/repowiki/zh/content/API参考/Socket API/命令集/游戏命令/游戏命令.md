## 游戏命令系统架构

游戏命令系统基于协议缓冲区（Protocol Buffer）实现，通过WebSocket进行通信。系统使用`ProtobufProtocol`类作为协议对象，包含消息ID和序列化数据。`ProtobufProtocolCodec`类负责编码和解码协议数据，将消息ID和数据字节数组写入缓冲区或从缓冲区读取。

```mermaid
graph TD
Client[客户端] --> |发送命令| Server[服务器]
Server --> Decoder[ProtobufProtocolCodec解码]
Decoder --> Handler[命令处理器]
Handler --> BusinessLogic[业务逻辑处理]
BusinessLogic --> Response[构建响应]
Response --> Encoder[ProtobufProtocolCodec编码]
Encoder --> Client
```

## 命令权限控制机制

游戏命令系统实现了严格的权限控制机制，通过继承`GameBaseHandler`和`GmBaseHandler`类来实现不同级别的访问控制。

### 普通玩家命令权限

普通玩家命令通过`GameBaseHandler`进行权限检查，主要验证玩家是否在线、是否正在登出以及功能是否开启。

```mermaid
flowchart TD
A[收到命令] --> B{玩家ID > 0?}
B --> |否| C[允许执行]
B --> |是| D[获取玩家对象]
D --> E{玩家是否正在登出?}
E --> |是| F[发送登出错误]
E --> |否| G{功能是否开启?}
G --> |否| H[发送功能未开启错误]
G --> |是| I[允许执行]
```

**图源**
- [GameBaseHandler.java](file://game\src\main\java\cn\game\games\net\game\handler\GameBaseHandler.java)

**本节源**
- [GameBaseHandler.java](file://game\src\main\java\cn\game\games\net\game\handler\GameBaseHandler.java)

### GM命令权限

GM命令通过`GmBaseHandler`进行权限检查，除了普通玩家的检查外，还额外验证玩家是否为GM账号。

```mermaid
flowchart TD
A[收到GM命令] --> B{是否生产环境?}
B --> |否| C[允许执行]
B --> |是| D{玩家ID > 0?}
D --> |否| E[允许执行]
D --> |是| F[获取玩家对象]
F --> G{是否为GM账号?}
G --> |否| H[抛出GM权限异常]
G --> |是| I[允许执行]
```

## 协议缓冲区序列化格式

游戏命令使用协议缓冲区（Protocol Buffer）进行序列化，确保高效的数据传输和跨平台兼容性。

### 命令协议结构

所有命令协议都继承自`IProtocol`接口，包含消息ID和序列化数据。

```mermaid
classDiagram
class IProtocol {
+int msgID
+byte[] serializeData()
+void deserializeData(byte[] data)
}
class ProtobufProtocol {
+Message data
+int seq
+int errorCode
}
IProtocol <|-- ProtobufProtocol
```

```mermaid

alt 玩家已在线
```

### 使用道具流程

```mermaid
sequenceDiagram
```
