## 简介
本指南旨在为新加入的开发者提供全面的入门指导，涵盖开发环境配置、项目构建、测试运行、服务器启动、核心业务流程理解、代码规范、调试技巧以及问题排查等内容。通过本指南，开发者可以快速熟悉项目结构和开发流程，高效地参与到项目开发中。

## 项目结构
本项目采用Maven多模块结构，主要包含以下几个核心模块：

- **core**: 核心功能模块，提供基础服务和通用组件
- **game**: 游戏服务器模块，处理游戏核心逻辑
- **login**: 登录服务器模块，负责用户认证和会话管理
- **util**: 工具类模块，包含各种通用工具和辅助功能
- **protocol**: 协议定义模块（通过pom.xml引用）

每个模块都有独立的`pom.xml`文件进行依赖管理，整个项目由根目录的`pom.xml`统一管理。

## 开发环境搭建

### JDK版本要求
根据`pom.xml`和启动脚本配置，本项目要求使用**JDK 21**版本。在`pom.xml`中通过`<release>21</release>`明确指定，同时在`game.sh`和`login.sh`启动脚本中也配置了相应的JVM参数。

### Maven配置
项目使用Maven进行依赖管理和构建。确保已安装Maven 3.6+版本。项目中已包含完整的`pom.xml`配置文件，无需额外配置。Maven将自动处理以下依赖：
- 内部模块依赖（core, game, login, util, protocol）
- 第三方库依赖（Vert.x, Spring, MyBatis, Netty等）
- 测试框架依赖（JUnit Jupiter, Testcontainers）

### IDE插件安装
推荐使用IntelliJ IDEA或Eclipse进行开发。建议安装以下插件以提高开发效率：
- **Lombok插件**：处理注解生成
- **Maven Helper**：可视化依赖关系
- **CheckStyle/SpotBugs**：代码质量检查
- **MyBatis Plugin**：Mapper文件导航
- **Protobuf Support**：协议缓冲区支持

## 启动本地服务器实例

### 配置环境
在启动服务器前，需要配置环境变量。项目提供了`init_env.bat`脚本用于初始化环境：

```bat
for /f "delims==, tokens=1,2" %%i in (env.txt) do (
	set %%i=%%j
	echo %%i=%%j
)
```

### 启动游戏服务器
使用`game.sh`脚本启动游戏服务器：

```bash
# 启动服务器
./game.sh start

# 停止服务器
./game.sh stop

# 重启服务器
./game.sh restart

# 查看服务器状态
./game.sh status
```

JVM参数配置包括：
- 堆内存：最大4GB，初始256MB
- 使用G1垃圾收集器
- 启用OOM时的堆转储
- GC日志记录到logs/gc.log

### 启动登录服务器
使用`login.sh`脚本启动登录服务器，命令与游戏服务器相同：

```bash
# 启动登录服务器
./login.sh start
```

登录服务器的JVM配置为：
- 堆内存：最大8GB，初始4GB
- 其他参数与游戏服务器类似

## 关键业务流程分析：登录流程
通过分析`登录流程.txt`文件，我们可以了解系统的登录业务流程：

### 登录流程步骤
1. **注册账号**（仅限官方渠道）
   - 请求地址：`10.12.175.84:9390/account/register`
   - 参数：用户名(account)、密码(pwd)
   - 返回：`{"ret_code":"0"}` 表示成功

2. **第三方确认登录**
   - 请求地址：`10.12.175.84:9390/account/third_party_confirm`
   - 参数：
     - channel：登录渠道（official或wechat）
     - token：登录凭证
   - 返回：包含`passport_session_id`和`user_id`

3. **获取服务器列表**
   - 请求地址：`10.12.175.84:9390/account/server_list`
   - 参数：`passport_session_id`
   - 返回：服务器列表，包含IP和端口信息

4. **连接游戏服务器**
   - 使用WebSocket连接到指定的游戏服务器
   - 使用Protobuf协议进行通信

### 实现要点
- 所有请求均为POST方法，参数以JSON格式放在请求体中
- 官方渠道需要先注册，微信渠道直接使用微信临时登录凭证
- `passport_session_id`作为会话标识在后续请求中使用
- 服务器列表可能返回多个地址，客户端可选择其中一个连接

## 调试技巧与日志分析

### 调试配置
启动脚本中已包含调试配置，可通过取消注释来启用：

此配置允许远程调试，端口为8011。

### 日志配置
项目使用Log4j2进行日志管理，配置特点：
- **游戏服务器**：使用简单的控制台输出，日志级别为error
- **登录服务器**：使用详细的滚动文件输出，按天和大小滚动

登录服务器日志配置包括：
- 控制台输出
- 标准输出日志（stdout.log）
- 错误日志（err.log）
- 警告日志（warn.log）
- 异步处理以提高性能

### 日志分析技巧
1. **定位问题**：首先查看`err.log`中的错误信息
2. **追踪流程**：通过`stdout.log`中的INFO日志追踪请求流程
3. **性能分析**：检查`gc.log`中的GC行为
4. **使用grep**：结合grep命令快速定位特定日志
   ```bash
   grep "ERROR" logs/err.log
   grep "user_id=1069838" logs/stdout.log
   ```

## 常见问题与故障排查

### 常见问题（FAQ）
**Q: 启动服务器时提示"JAVA_HOME not set"**
A: 在`game.sh`或`login.sh`中取消注释JAVA_HOME配置，或确保系统环境变量已设置。

**Q: Maven构建失败，依赖下载超时**
A: 检查网络连接，或配置Maven镜像仓库。

**Q: 登录返回ret_code非0**
A: 检查channel和token参数是否正确，微信渠道需要有效的code。

**Q: 无法连接到游戏服务器**
A: 确认服务器列表返回的IP和端口是否正确，防火墙是否开放相应端口。

### 故障排查手册
1. **服务器无法启动**
   - 检查端口是否被占用
   - 查看`out.log`中的启动日志
   - 确认JDK版本是否正确

2. **性能问题**
   - 分析`gc.log`中的GC频率和暂停时间
   - 使用JProfiler进行性能剖析（已配置在启动脚本中）
   - 检查线程池使用情况

3. **内存溢出**
   - 检查`oom.dump`文件（已配置HeapDumpOnOutOfMemoryError）
   - 使用内存分析工具（如Eclipse MAT）分析堆转储
   - 优化数据结构和缓存策略

4. **网络问题**
   - 使用netstat检查端口监听状态
   - 使用telnet测试端口连通性
   - 检查防火墙设置

## 扩展开发指南
鼓励贡献者遵循既定模式进行扩展开发：

1. **遵循模块化设计**：新功能应根据业务领域划分到合适的模块
2. **保持代码风格一致**：遵循现有代码的命名规范和设计模式
3. **编写单元测试**：为新功能编写充分的测试用例
4. **更新文档**：及时更新相关文档和注释
5. **使用Apollo配置中心**：运行时配置应通过Apollo管理
6. **遵循Vert.x异步编程模型**：避免阻塞操作，合理使用Event Bus

通过遵循这些指导原则，可以确保代码库的可维护性和可扩展性。
