# 普通充值跨进程与崩溃恢复验收

## 验收对象

选择普通充值兑换 `PayType.Recharge` 的发货链路。配置 `Recharge.xml` 中 ID=1 对应 6 元、SKU 1001、60 钻石（资产 100001）。测试准备一条已保存的合法待发货订单和 100 钻石基线；奖励通过正式 `ServerHandler`、`PayType.Recharge.offlinePay`、`PlayerHelper.addResources` 及同步 `Charge` 事件执行。

提交后的固定预期：钻石 160、累计充值 6、充值次数 1、VIP 等级 1、剩余 VIP 经验 0、有效完成凭证 1。重复同一订单不得再次增加这些字段。订单的 addId/addCount 保持正式创单默认值；奖励数量来自当前配置，不由测试回调直接加资产。

发送节点和处理节点是两个真实 JVM，通过 Zookeeper 集群中的正式 Vert.x 编解码与消息分派通信。目标先经过入站调度，再由 ship 投递到玩家邮箱。每个新目标进程由真实 Mapper 冷读，构造 Player、登记玩家，并执行独立表查询和正式模块恢复钩子；新进程自身在玩家邮箱提供资产、订单和 Charge 字段观测。父进程另用新数据库连接冷读作独立对照。

## 场景与通过标准

| 场景 | 预期 |
|---|---|
| 同订单重复跨进程发货 | 两次成功、实际奖励执行一次；资产及全部充值字段只增加一次 |
| 保存成功后强制退出并重启 | 新实例在重试前已恢复全部字段；重试成功且新实例奖励执行次数为 0 |
| 发奖后保存前，发送端等待超时 | 发送端实际 TIMEOUT；远端继续原任务。释放故障门后同单重试成功，资产只增加一次 |
| 提交完成、回复发送前退出 | 完成凭证及奖励已在库；新实例同单成功去重，不重新执行业务 |
| claim 后、奖励前退出 | 保留 claim；资产为基线、无 receipt；新实例重复请求拒绝自动补发 |
| 奖励后、保存前退出 | 先观测内存 160，再强制终止；新实例恢复 100，无 receipt；同单拒绝自动补发 |
| UPDATE 与 receipt INSERT 后、commit 前退出 | 真实事务未提交，聚合与 receipt 回滚；独立 claim 保留；新实例保持待核对状态 |

这些场景由 6 个 JUnit 方法覆盖，正常保存重启与重复请求合并在同一方法。故障门由目标进程在实际边界原子发布；父测试核对进程身份及内存字段后强制结束该进程，确认退出，并等待发送方真实集群视图移除旧成员后才启动继任实例。强杀后 Zookeeper 租约和路由需要收敛，不承诺瞬时恢复，也不通过盲目重发交易来探测路由。数据库凭证经正式 lookup 校验参数、身份及证明，不能只凭行数认定完成。

## 数据损失与恢复约定

- **已提交**：本次奖励、热订单和完成凭证同事务保存。业务进程退出后可恢复；调用端未收到回复时仍按原订单去重。
- **尚未提交**：内存奖励可能丢失，恢复到最后一次已确认快照。本链路的独立 claim 不随进程过期；结果保持待核对，不能把支付视为成功，也不能自动重发。实际补偿需先核对平台与数据库事实，沿现有受信恢复规则处理。
- **结果不明**：发送端请求超时不能证明数据库失败，也不等于数据库 UNKNOWN。本轮的发送端超时与确定 commit 前/后的退出分别记录。
- 定时保存周期不是最大丢失窗口保证；本轮不据此给其他业务承诺“最多丢五分钟”。

## 运行与证据

入口：`.ai-workspace/scripts/run-payment-process-tests.ps1`。默认从本机 Apollo 的 game/SYQ/jdbc、zookeeper 读取连接配置。只创建随机玩家 ID、专用 claim/receipt 表和随机 Zookeeper rootPath，不向公共 Game 地址注册。凭据放在本轮私有目录，执行结束删除；报告不包含密码或支付平台令牌。

每次执行使用新目录 `.ai-workspace/.runtime/payment-process-recovery/<runId>`。保留 JUnit 报告、各节点日志、就绪身份、故障点及逐场景 evidence.json。场景通过与清理通过分别记录，最终 passed 必须两者都成功。清理只结束本轮持有的进程句柄；全部退出后，校验归属再删除本轮玩家、临时表及集群命名空间。

在已登记的任务内使用 Task Run 执行，保留失败与复测历史。方法清单为 `game/src/test/resources/payment-process-recovery-expected.json`，零执行、缺失或跳过不能通过。原始日志仅本机保存，提交的验收记录采用白名单摘要。

本轮同时补齐版本控制中遗漏的 `CborSnappyUtil` 及其原有四项单元测试。此前已提交的 Player 和 PlayerDataSnapshot 已引用该工具；工具仅留在本地会使干净检出无法编译。补入文件保留原有实现，并用 `util/src/test/resources/cbor-snappy-expected.json` 核对实际测试执行。

## 结论适用范围

本轮使用专用业务启动器，验证服务端发货请求到实际奖励、存储及新进程恢复。它不包含客户端创单、真实支付平台扣款/验单、完整 Game/Login 启动，也不验证 Redis 路由归属、旧节点仍存活时的接管或跨节点并发写权。继任目标启动前必须确认前任已死亡。进程强制退出不等价数据库断电测试。

夹具为独占的新玩家，既有任务/活动及独立表记录为空；不据此宣称所有活动奖励、邮件副作用或所有玩家历史数据均已验收。保留全部生产模块及恢复钩子，核验本次实际发生的钻石、VIP 与累计充值副作用。
